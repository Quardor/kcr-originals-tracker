# kcr-frontend

SPA фронтенд сервиса контроля передачи оригиналов документов (KCR Originals Tracker).
Работает поверх REST/WebSocket API бэкенда `server/kcr-backend` (префикс `/api/v1`);
запросы `/api/v1/ai/**` бэкенд сам проксирует в сервис ИИ-помощника `ml/` — браузер с ним
напрямую не общается. Состояние описания — 2026-11-28.

## Стек

- React 18 (JavaScript, без TypeScript) + Vite 6
- react-router-dom 7 — маршрутизация
- без UI-библиотек и CSS-фреймворков — единый `src/styles.css`
- без axios — fetch-обёртка с автопродлением JWT (`src/api/client.js`)
- без ESLint/Prettier и без тестов (известный пробел — п. 56 §10 ARCHITECTURE-FULL.md бэкенда)

## Возможности

- вход и самостоятельная регистрация (регистрация создаёт оператора);
- справочник клиентов: поиск по коду KCR/ИНН, фильтры (тип, KCR действует/заблокирован,
  признак, этап работы, ответственный — любой/только мои/свободные), сортировка, пагинация;
- карточка клиента: все поля, блок работы (взять в работу, этап, переназначение и освобождение
  ответственного — админ), единая история с датой, временем и автором (звонки с результатом,
  договорённостью, сроками и ссылкой на запись; письма; комментарии; системные события),
  форма события, претензии с санкциями, AI-сводка перед звонком, таблица срезов;
- «Сегодня нужно» (`/today`): клиенты с наступившим сроком следующего контакта — оператор
  видит своих, администратор всех;
- список на обзвон (`/call-list`): для оператора — закреплённый общий пул с кнопкой «Взять
  в работу», для администратора — ещё и вкладка составления (фильтры по долгу, доле
  непереданных, динамике, типу и поиску; предпросмотр; закрепление; очистка);
- ИИ-помощник (через бэкенд): чат по данным (`/ai`, WebSocket-стриминг, таблицы-выборки),
  аналитика (`/ai/analytics`, обе роли), приоритизация (`/ai/prioritize`, админ), сводка
  в карточке, экспорт отчётов в xlsx;
- создание и изменение клиента (только администратор; PATCH — только изменённые непустые
  поля, очистить поле через интерфейс нельзя);
- импорт из Excel (только администратор): предпросмотр без записи и применение, отдельные
  выгрузки клиентов и срезов (у срезов — отчётный период и дата среза), файл до 10 МБ.

## Маршруты

| Путь | Страница | Доступ |
|---|---|---|
| `/login` | Login | публичный |
| `/clients` | Clients (редирект с `/`) | обе роли |
| `/clients/:id` | ClientCard | обе роли |
| `/clients/new`, `/clients/:id/edit` | ClientForm | админ |
| `/today` | Today | обе роли |
| `/call-list` | CallList | обе роли (составление — админ) |
| `/ai` | AiChat | обе роли |
| `/ai/analytics` | AiAnalytics | обе роли |
| `/ai/prioritize` | AiPrioritize | админ |
| `/import` | Import | админ |
| прочие | NotFound (404) | — |

Роль и имя пользователя берутся из claims access-токена (`sub`, `preferred_username`,
`roles`). Ограничение по роли в интерфейсе (`Protected adminOnly`, скрытые кнопки) — только
удобство: настоящая проверка прав выполняет бэкенд.

## Запуск (разработка)

Нужен запущенный kcr-backend (`:8080`); для AI-страниц kcr-ml должен быть доступен бэкенду на
`http://localhost:8000` — сам браузер в него не ходит. CORS в dev разрешает origin
`http://localhost:5173` только у бэкенда.

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # прод-сборка в dist/
npm run preview    # локальный просмотр собранного dist/
```

Адреса задаются переменными окружения Vite (файл `.env` в каталоге проекта, шаблон —
`.env.example`):

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `VITE_API_BASE_URL` | `http://localhost:8080/api/v1` | REST API бэкенда (AI-маршруты `/ai/**` — те же origin и `apiFetch`) |

Порт 5173 общий у dev-сервера и контейнерного стенда — работать одновременно они не могут.

## Контейнерный стенд

В едином стенде монорепозитория (см. [docker-compose.yml](../../docker-compose.yml) в корне
репозитория) фронтенд собирается в образ nginx: статика SPA + обратный прокси, весь
`/api/v1/**` → kcr-backend (в том числе `/api/v1/ai/**`; для `location = /api/v1/ai/chat` —
upgrade до WebSocket и таймауты 1 ч). Браузер ходит только на
`http://localhost:5173` (один origin), CORS не участвует; в образ запекается относительный
адрес `VITE_API_BASE_URL=/api/v1`. Лимит тела запроса
в прокси — 20 МБ (бэкенд принимает файлы до 10 МБ и отвечает 400 в едином контракте).

## Структура

```
src/
├── api/          — доступ к API: client.js (fetch-обёртка; refresh-ротация single-flight
│                   в пределах вкладки и через Web Locks между вкладками — параллельный
│                   refresh отзывает семейство токенов), auth.js, clients.js, events.js,
│                   claims.js (претензии, санкции, справочник пользователей), worklist.js,
│                   imports.js, ai.js (ИИ-помощник через бэкенд: REST через общий apiFetch —
│                   тот же refresh по 401, экспорт xlsx, чат-WebSocket по одноразовому
│                   ticket `POST /ai/chat/ticket`), errors.js (коды ошибок → русский текст)
├── auth/         — сессия: jwt.js (декод claims: id, имя, роль), AuthContext.jsx
├── components/   — Layout, Protected, Pagination, ui.jsx (Spinner, ErrorBox, бейджи),
│                   EventForm, HistoryFeed, ClaimsSection, BriefSection
├── labels.js     — русские подписи справочников (этапы, типы событий, результаты звонков,
│                   статусы претензий и санкций, категории динамики, инструменты чата)
└── pages/        — Login, Clients, ClientCard, ClientForm, Import, Today, CallList,
                    AiChat, AiAnalytics, AiPrioritize, NotFound
```

`labels.js` зеркалит enum'ы бэкенда: расширение справочника требует правки в двух местах.

## Известные ограничения

Подробности — п. 52, 56 и 63 §10 [ARCHITECTURE-FULL.md бэкенда](../../server/kcr-backend/ARCHITECTURE-FULL.md):

- нет границы ошибок рендера (ErrorBoundary) — исключение в рендере даёт белый экран;
- «Составить список» отправляет текущие фильтры, а не те, по которым сделан предпросмотр;
- таблица предпросмотра импорта срезов выводит все строки разом; фильтр периода в карточке —
  точное совпадение на сервере; карточка не показывает категорию динамики среза;
- классы `btn-sm` и `checkbox-label` используются в `CallListPage`, но не описаны в `styles.css`.
